## 尚未齐备的外部输入

| ID | 输入 | 为什么必须独立跟踪 |
| --- | --- | --- |
| D01 | IEEE 802.3 被引用条款及 802.3dj D1.4 基线 | UALink PDF 没有重复完整 PCS/FEC/PMA 定义；不能把任意新版 Ethernet IP 当作逐位等价替代 |
| D02 | UALink gNMI 扩展、YANG、SAI 头文件及与 2.0 匹配的版本 | 基础 OpenConfig gNMI v0.14.1 文件已在线核查，不含 UALink Control 扩展；完整依赖树、官方扩展来源、提交哈希、许可待锁定 |
| D03 | Redfish 精确映射、UEFI CPER 2.11 或更高、密码学引用与向量 | 已核对 NIST SP 800-38D 正式算法以支持 A07；完整 KMAC/GCM 与 UALink 位精确向量、密钥使用预算、CPER/Redfish 和 INC 数值参考仍未齐备 |
| D04 | 原子操作的本地内存接口契约 | 普通 Atomic 的具体操作类型含实现定义语义；协议传输正确不等于已经实现某 NPU 的全部内存原子操作 |
| D05 | 获授权的独立 UALink 2.0 VIP/对端或一致性向量 | 自研 RTL 与自研 VIP 可能共享同一个错误；本地回归不等于第三方互操作或联盟认证 |
| D06 | 目标工艺/器件、工具、SRAM/SerDes/时序库与角点 | 决定真实 PPA、时钟、管脚时延及模拟 PHY 能力；目前无已选定器件或可引用的 STA 成绩 |
| D07 | 实施和公开发布权利、项目源代码许可证 | 评估版获取不自动完成实施、第三方 IP 和再分发权利审查；PDF 和抽取文本继续私有隔离 |

许可信息仅做工程风险提示：[官方评估协议](https://ualinkconsortium.org/specification/ualink-common-2-0-specification/) §2.1、§2.2（2026-09-07 核查）规定内部评估授权，并说明该协议不独立授予实施权利；非会员选择实施仍需自行承担取得必要第三方权利的责任。这不等于本报告断言“必须入会才能实现”，具体决定由负责人进行许可审查。

# KD28 逻辑存储映射数字仿真复核

本复核仅验证 `kd28_fifo_sdp_storage_map` 接到授权 KD28 真实功能宏模型后的逻辑存储行为。被测源码、固定宏封装以及 SDP/SP/TDP 模型均来自显式 `--kd28-root`；测试台没有用简化宏代替实际模型，也没有引用形式验证入口或其参考算法。它不构成 macro STA、模拟 SRAM 签核、FIFO CDC 证明、UALink 联盟认证或完整 Endpoint/Switch 完成声明。

## 可移植执行入口

```sh
python3 verification/sram_storage_map/run_simulation.py \
  --kd28-root /authorized/KD28/project --label storage_mapping --jobs 2
```

从任意当前目录启动入口时，输出仍相对本仓库根目录解析。必须安装 Python 3、Icarus Verilog 与 VVP；可用 `--iverilog` / `--vvp` 指定工具。默认矩阵是宽度 `8,32,40,256,512,600` 与深度 `1,2,3,5,255,256,257,511,512,513,1024,1025,2048,2049,4097,65535` 的完整笛卡尔积，共 96 个正常组合，外加 2 个实际注错组合。当前入口使用生产包装器参数：`logical_depth=depth`、`mapped_depth=max(2,depth)`、`address_width=depth.bit_length()`，因此二次幂深度保留一个额外的地址高位。合法刺激始终限定逻辑深度；深度 1 仍只有一个可用逻辑地址。`--widths`、`--depths`、`--seed`、`--random-steps` 可显式调整范围；默认 seed 为 73129，每个参数组合派生 seed 是 `73129 XOR (width << 16) XOR depth`，每个组合另含 512 个伪随机操作。`--mode mutations` 或 `--mode positive` 可分阶段执行，报告分别列明实际计划和完成数。

输出为 `reports/sram_storage_map/simulation_<label>/summary.json`、每个参数目录的 `result.json`、`vectors.txt`、`compile.json`、`compile.log`、`simulation.json`、`simulation.log`、`simulation.vvp`。运行目录还保留工具版本、入口及测试台快照、输入来源和 SHA-256。每条刺激只包含时钟边沿、使能、逻辑地址及写数据，没有外部计算好的读预期。已有 label 直接拒绝，因此失败证据不会被下一次运行覆盖。

外部模型只复制到本地受限运行目录，目录权限为 0700，模型副本权限为 0600；隔离副本上的注错不修改外部原文件。结束时重新校验外部源文件哈希。受限源快照与二进制留在本机忽略的 `reports/` 中，不属于可分发仓库源代码。

## 独立参考与覆盖定义

`simulation_tb.sv` 内独立保存 `memory[0:DEPTH-1]`，直接使用逻辑地址。被测 mapper 的 `DEPTH` 与 `ADDR_WIDTH` 由独立参数 `MAPPED_DEPTH` 和 `ADDR_WIDTH` 显式传入；TB 返回实际 `dut.DEPTH` 与 `$bits(dut.write_addr_i)`，入口核对其是否等于记录的生产实例参数。物理深度 2 的逻辑单字配置不会把额外物理字加入参考容量。参考读在同一个操作的参考写之前取得旧值，因此同沿同地址比较 read-before-write；独立写沿、独立读沿、同沿以及无边沿操作都由刺激显式控制。首次有效读前不约束无复位读输出，所有读地址均先经过真实写入初始化；已知预期后使用 `!==` 比较整个逻辑字，未知实际值同样失败。

每个正常组合执行：

- 全部合法地址的随机整字写入、全地址反序读回、随机操作后的全地址正序读回。读写地址覆盖分别要求 `DEPTH/DEPTH`，不是抽样代表点。
- 首尾地址全部 `WIDTH` 位的 walking-one 和 walking-zero，以及全零和全一。独立统计实际读输出每位都出现过 0 和 1，要求 `WIDTH/WIDTH`。
- 首尾地址、固定宏深度转换附近、每个 2048 字银行边界两侧的读写、禁止写入、同沿同地址读先于写与随后新值读回。
- 读使能低时改变地址/银行，分别施加无时钟边沿、读边沿和双时钟边沿；比较读输出保持。初始化后还专门读取地址 0，再以 `read_cs=0` 切换至末地址，保证多银行配置直接激励停读银行切换。
- 读使能高但没有读时钟边沿时，写操作不能使读输出更新。边沿前、边沿后都比较有效的完整读字。
- 512 个可复现随机操作，包含独立/同时/缺失时钟边沿、随机读写使能、全宽数据、合法地址以及同地址偏置。

物理高位填零属于单独的补充检查：有效读后遍历实际 `bank_read_data` 中超出逻辑字的填充位并要求为 0。该检查通过被测模块的物理常量和银行寄存器定位填充位；平坦逻辑 scoreboard 的整字预期不依赖这些物理常量。计数 `padding_checks` 的单位是一次有效读的全部填充位检查，不是位数，也不是代码覆盖率。

## 注错检查器敏感性

两类注错只改运行目录中的真实 mapper 副本，继续编译和运行相同固定宏与真实行为模型：

| 注错 | 实际配置 | 改动与必须检出的行为 |
|---|---|---|
| `data_lane` | width 40 / depth 5 | 在实际宏 D 端每个 lane 的 bit 0 异或 1；逻辑低 lane 与尾部 partial lane 都受到影响，完整字比较必须失败 |
| `read_bank_bypass` | width 40 / depth 2049 | 用当前组合银行选择旁路 `read_bank_q`；停读切换到地址 2048 时，上次读出的银行数据必须仍保持 |

注错通过门槛要求 `compile.returncode == 0` 且 VVP 实际非零退出，并出现整字、边沿前保持或填充位比较失败。语法错误、缺失输入、覆盖不足、超时、任意错误返回值或伪造的失败标记都不能算检出。注错日志与正常日志完整保留。

## 限制与后续

这些计数是参数矩阵、地址、逐位取值和操作覆盖，不是语句/分支/翻转代码覆盖率，也不是所有输入序列的穷举。96 个明确列出的参数组合通过不代表所有宽度和深度均得到证明。仅使用合法逻辑地址；无效地址、未知输入、模拟时序窗口、SDP 异步碰撞的物理行为和电源状态不在当前验证承诺内。SP/TDP 源文件因完整固定宏库解析一并输入，实际 mapper 只实例化 SDP，因此这里没有新增 SP/TDP 行为通过声明。

独立/同沿时钟操作是 mapper 数字功能检查；当前 UALink FIFO 组合的共同上升沿时钟约束仍应在 FIFO 层报告。下一步将本结果与独立形式证据对照，并在实际发送 256/512 位、接收 600 位 FIFO 组合及 Endpoint/Link 路径中检查集成后的行为。宏 Liberty/STA、物理 CDC 与完整 Endpoint/Switch 关闭工作需要各自的证据。

# Endpoint burst fault integration candidate review

The candidate changes only `upli_endpoint_ip_top.v`: five public ports (two external classification inputs and three diagnostic outputs), one frozen native burst monitor instance, and the OR into existing Request order-diagnostic bit. The existing controller remains the only role Drop and notification owner. Source Command and Num fields already survive the native envelope, but the available bridge decoder only implements ordinary Read/Write/WriteFull. It cannot safely qualify every native command for this monitor. Explicit same-event classification therefore remains a required API boundary; no new opcode table is invented.

`results/final_non_tl` and `results/final_tl` each pass PORTS 1/2/4. Combined coverage is 558 explicitly checked native input edges, 122 Requests, 212 OrigData beats, 54 first-fault injections and 3,656 assertions. Initialization, reset and waiting clock cycles are additional and are not included in that checked-edge count. The lengths 1..4 run from each configured starting port. Tests retain full error Data through the advertised final beat, vary idle classification, and overlay a no-data Request with a different VC on an older tail. Nine first-fault scenarios cover unknown classification, absent first Data, orphan Data, wrong first Offset/Last, missing tail, wrong tail VC/Offset/Last. Each compares exact 10-bit current/sticky diagnostics, all-role/all-port scope, first-error receive rejection, notification acknowledgment without recovery, and common reset cancellation. Expected fault bits and scope are directed independent constants; parity is recomputed from complete native fields in the TB, with additional assertions excluding control/auth-profile errors as an explanation for Drop. No DUT internals provide expected values.

The test uses the real connection sides, native RX protection, four ordered receive channels, SRAM storage, credit initialization and the existing bridge/collector. It deliberately leaves the backend and TX candidate interfaces inactive. It does not establish end-to-end transaction execution or re-prove complete credit return conservation. The monitor connects raw events, never registered receive acceptance or SRAM retirement; observed rejected receive events on the first fault support the intended pre-edge Drop behavior. New observer diagnostics feed existing `kind_order[0]`, hence existing reason bit20; the new full 10-bit output records precise local cause. This mapping is local consistency policy, not a new native parity encoding.

All six configurations pass Verilog-2001, strict Verilator `-Wall` and Yosys `hierarchy/proc/opt/check -assert/stat`: 18 static checks. Hierarchy evidence confirms one role fault controller, one RX TDM monitor, one new burst monitor, four native RX channels, four ordered receive channels, four credit banks, two connection sides, one station TX and one request bridge; zero latches. Credit bank count is unchanged. This is structural synthesis checking, not timing or SRAM mapping signoff.

Three actual candidate-top mutations compile and fail the self-check: removing the burst-to-controller OR (checked edge13), forcing TL scope in non-TL mode (13), and replacing native NumBeats with zero (2). `missing_red` preserves old-production-top elaboration failures for all three port configurations due to the absent classification/diagnostic API. Initial `matrix_*` failures were real TB collateral errors: opaque Command3f reached the existing ordinary-only bridge and independently requested Drop. The TB now uses that bridge's already documented Command28/03 and matching LEN geometry while leaving monitor classification explicit. The bridge and production RTL were not changed. Intermediate diagnosis reads were only failure printouts, removed from the final expected-value path.

The manifest freezes exactly one production replacement, plus local runner/TB/source generator/contracts and evidence identities. The runner snapshots the candidate top together with current production dependencies; external KD28 sources are verified against the existing authorized dependency manifest and are not installable source changes. Review `top.patch` before applying. Existing callers must now supply classification from the same raw RX Request event; a valid request marked unknown is intentionally fatal. A falsely asserted known/no-data classification is not detectable without its external decoder. Inputs must obey ordinary synchronous timing; classification is not a later SRAM-head attribute. The monitor freezes after first error and does not own recovery. Isolated LinkDown/Isolation, exceptional burst abort, Atomic/INC command interpretation, backend execution, formal verification and STA remain outside this checkpoint.

Reproduce from any cwd with `python3 /PATH/UALink/build/development/upli_endpoint_burst_fault_integration/run.py --label NEW --kd28-root AUTHORIZED_KD28 --static`, then repeat with `--tl-mode 1`. Use `--ports 1 --fault burst_disconnect|scope|burst_num` for the three checker injections. Expected result and source/artifact SHA files are under this candidate's `results/LABEL/`. Root review and explicit caller adaptation precede production installation; this task neither changes production nor commits files.

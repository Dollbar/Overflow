# Executable typed-TL classification boundary

This candidate is an actual classification/context and full-record holding stage, not an automatic prepared source reconstruction. `switch_egress_tl_context` takes the physical typed-egress record as its unchanged 544-bit bundle `{local_dl_header24,aux6,msg2,flit512}`, plus token/VC/response/last. It reuses one existing `tl_receive_context` (and therefore one `tl_sequence`) per physical port. Parameters PORTS and VCS independently support1/2/4; TOKEN_WIDTH is positive. i_auth[PORTS] is stable between common resets.

Input classification uses raw lower flit[255:0], msg[513:512], Message types[7:0]/[263:256]. Local header/aux/token/VC/class/Last are preserved, not interpreted as standard TL field boundaries or next-hop headers. Each port holds one accepted full record and the exact pre-capture pending count7, BE sequence73, release metadata584, proposed demand/release vectors80+80, two half classes6 and store indication. Low slices belong to port0; lower-half class occupies bits[2:0], upper bits[5:3]. Classes are existing RTL codes: Control0/Data1/BE2/NOP3/Message4/Poison5/Auth6/invalid7. The retained context vectors are proposals/observations, never actual credit debit/return commands.

`o_captured=i_valid&&o_ready` alone commits TL classification/context and stores the record atomically. `o_retired=o_valid&&i_ready` transfers the saved classified record downstream. Backpressure does not commit, and simultaneous retire/capture replaces the one entry. Both events are distinct from upstream queue release and all prepared/wire events. No credit bank, Drop state, DL scheduler, prepared TX or backend is added. Invalid configured sideband VC or rejected existing TL classification sets per-port error and sticky fail-stop; it cannot be captured. An older accepted output may still drain. Other ports continue. Reset cancels holdings/context/errors together. A valid unknown/reserved/unsupported tenure remains rejected; this does not extend the existing classifier's protocol profile.

The physical stream must be suitable for the existing TL sequencing grammar. Classification alone cannot establish that arbitrated records from independent ingress streams belong to the same transaction or match packet Last. Packet token/class are local metadata, not reconstructed per-field ownership. Auth payload bits, Data poison pairing, command/address legality, routing semantics and complete tag-to-field association are not checked by this boundary. Unsupported or incomplete mappings remain explicit.

Prepared-side boundary remains open. Per egress `tl_tx_prepared` needs Request/Response source_valid2, source_control512(two256-bit groups), source_tags_valid2 and source_tags1024(two8×64-bit groups), plus per-class half-counts i_data_valid4 and two data buses512(each two class-specific256-bit halves). A future assembler must recover/reorder complete fields, associate every Auth tag and ordered Data/BE half, split mixed-class Control groups without losing natural starts, preserve old-tail/new-header ordering and validate capacity/profile before presenting these sources. A one-record output does not contain a complete reconstructed source group in general.

Ownership must remain: (1) this boundary captured a packed record; (2) future assembler accepted its classified record; (3) prepared `o_source_captured` atomically accepted a complete Control group and applicable tags; (4) `o_data_accepted` accepted the exact per-class half counts; (5) prepared header/tags/data_taken consume real queued sources only on final TL send confirmation. Data admission may be independent of Control capture; neither can release an unrelated descriptor. `o_group_queued` and partition_taken are additional separate events, not source-capture synonyms. Authentication mode cannot synthesize zero tags or reuse arbitrary upper flit bits without field-level association.

The existing Endpoint shows the confirmed downstream chain: prepared TX flit/msg -> `tl_credit_admitted_port` -> actual first-payload `dl_replay_data_port` acceptance. Replay must not recapture prepared sources or debit TL credits. The old local DLheader is not reused as a new-hop header; the new DL owner constructs it. FC publication/receive credit configuration also requires an actual per-port owner. No direct connection from this boundary to that chain is claimed. Machine-readable status keeps prepared reconstruction, actual TL sending and DL attachment unimplemented.

Outputs immutable sources/vectors/logs/static/summary/hashes under build/verification/ip_tops/switch_egress_tl_context/NEW. Next implement a confirmed field/Data/Auth assembler at the explicit retained-context output, then connect its separate ready/capture/admission events to actual prepared and credit/DL owners.

Exact next-owner interface, per physical egress:

| Actual prepared port | Required source and acceptance |
| --- | --- |
| `i_source_valid[1:0]`, `i_source_control[511:0]` | lane0 Request / lane1 Response, each a complete256-bit source group; hold until corresponding `o_source_captured` |
| `i_source_tags_valid[1:0]`, `i_source_tags[1023:0]` | each lane eight64-bit source tags; Auth capture atomic with Control; `o_source_tags_taken` is capture-time ownership |
| `i_data_valid[3:0]`, `i_data0[511:0]`, `i_data1[511:0]` | each lane's2-bit count0/1/2 selects ordered256-bit halves from data0/data1 at lane*256; consume only `o_data_accepted[lane*2+:2]` |
| `i_available`, `i_capacity`, `i_done`, `i_shared`, `i_auth`, `i_pending`, request/response budgets | actual per-port initialized credit/context state and capacity; no values can be inferred from this record's token or queue counters |
| `i_fc_valid`, `i_fc_flit`, `i_fc_msg` | independent real FC publisher; consume only `o_fc_taken` |
| `i_taken` | actual admitted first transmission; prepared `o_header_taken/o_tags_taken/o_data_taken` are final source consumption, separate from all above admission events |

`o_source_ready` alone is not capture; `o_group_queued/o_partition_taken` are internal downstream queue admission observations, not wire events. Common reset must cancel every new assembler descriptor and all corresponding prepared/credit/DL owners together; this leaf implements only its local cancel. Incoming records from independently sequenced ingress links need an upstream, field-aware association/reordering design before sharing one outgoing TL context. This remains an integration precondition, not a capability inferred from these tests.

# Switch physical egress scheduler contract

Candidate only; no production/inventory edits. Parameters PORTS=1/2/4, VCS=1/2/4, DATA_WIDTH>0, TOKEN_WIDTH>0, RSP_BURST_MAX=1..15 (default2, zero rejected). Native local slot layout remains slot=(response*VCS+vc)*PORTS+egress. response0=Request,1=Response. This component does not parse TL or claim standardized QoS.

Inputs i_clk/i_rstn, i_valid[2*VCS*PORTS], i_data[slots*DATA_WIDTH], i_last[slots], i_token[slots*TOKEN_WIDTH], i_ready[PORTS]. Outputs o_ready[slots] back to the actual queue, o_valid/o_last/o_response[PORTS], o_data[PORTS*DATA_WIDTH], o_token[PORTS*TOKEN_WIDTH], o_vc[PORTS*2], o_selected[slots], o_owned[PORTS]. Synchronous low reset gates public outputs immediately and clears ownership/round-robin/quota on the edge; reset must be shared with queue epoch. No release, reservation, credit or account ports exist.

Each physical egress independently chooses a visible queue head. First valid presentation is independent of physical ready; first-beat stall captures owner at the edge, so a later higher-priority arrival cannot replace the stalled packet. Once owned, keep its class/VC through bubbles and backpressure. Only i_valid(selected) && i_ready(egress) && i_last(selected) ends the packet. Idle and valid0 Last noise never advance pointers or release owner. o_selected still indicates an owned slot in a bubble; o_ready passes physical ready only to that slot. Invalid data/token/last/VC/response outputs are zero. Inputs must obey producer hold stability when valid&&!ready and preserve packet token/last semantics; the scheduler cannot reconstruct an unknown packet length or recover a malformed source.

At a new packet boundary, prefer Response while its consecutive completed-packet count is below RSP_BURST_MAX, or whenever no Request is ready. If both classes have visible candidates and the saturated Response count reached the bound, choose Request; a completed Request clears that count. Class-local VC round-robin pointers advance only when an actual packet last is accepted. Response-only traffic saturates the quota, so a newly arriving Request gets the next free opportunity; no artificial idle slot is inserted. Within each class a persistent visible VC is selected within VCS services of that class.

Fairness is in complete-packet service opportunities, not fixed cycles/bytes. A persistent eligible Request waits at most RSP_BURST_MAX intervening Response completions at a free boundary, plus preceding Request VCs; both classes and all eligible VCs have finite service under finite packets and eventual downstream ready. An already owned packet is never preempted; if its producer never supplies a valid last or downstream never accepts, no cross-class progress bound is claimed. Request traffic cannot consume Response buffer capacity (queue responsibility); this scheduler still shares the physical link bandwidth and packet lock. It provides bounded Response preference without Request starvation, not absolute Response bandwidth or a network-level deadlock proof.

Integration: connect queue o_valid/data/last/token to scheduler inputs, scheduler o_ready to queue i_ready, and physical sink ready to scheduler i_ready. Existing queue alone generates release after its selected last-word dequeue; never add a second release/reservation for scheduler completion. Header/body ownership remains in vc_queues and output packet ownership lives here at a distinct later boundary.

Run python3 verification/ip_tops/run_switch_egress_scheduler.py --label NEW --faults. Outputs build/verification/ip_tops/switch_egress_scheduler/NEW source snapshots/vectors/logs/static/hashes; next root review and separately authorized top installation. No STA/PPA or protocol certification claim.

# Fixed SRAM mapper formal evidence review

This review covers the actual authorized `kd28_fifo_sdp_storage_map` source,
its fixed SRAM black-box declarations, and the proof generated by
`verification/sram_storage_map/run_formal.py`. Production RTL and the external
KD28 dependency were not edited. This is a common-clock macro-interface mapping
theorem; it is not a memory-content, physical SRAM, or complete FIFO theorem.

Final result: **95/96 exact configurations formally proved and independently
audited**. Width 600 at depth 65535 remains unproven after bounded-runtime
solver and preprocessing attempts. Separate production-parameter behavioral
simulation passed 96/96 cases with 2/2 source mutations detected; separate
production binding evidence covers 24 configurations. Those separate results
do not close the remaining formal case. All 23 audit tests passed in normal
and optimized Python. The machine-readable final record is
`build/verification/sram_storage_map/formal_audit_reports/formal_summary.json`.

## Independent audit entry

`verification/sram_storage_map/check_formal.py` imports no runner code and uses
no runner geometry, property-generation, inventory-generation, or audit helpers.
It requires the intended widths and depths on its command line and checks the
exact Cartesian product, duplicate/missing/extra result rows, and case folders.
The input manifest is not allowed to define its own coverage denominator.

For example, from the repository root:

```sh
python3 verification/sram_storage_map/check_formal.py --stage build/verification/sram_storage_map/first_healthy --widths 40 512 --depths 3 2049
python3 verification/sram_storage_map/check_formal.py --stage build/verification/sram_storage_map/data_fault_bounded --widths 40 --depths 3 --fault data
python3 verification/sram_storage_map/check_formal.py --stage build/verification/sram_storage_map/bank_fault_bounded --widths 40 --depths 2049 --fault bank
python3 verification/sram_storage_map/check_formal.py --stage build/verification/sram_storage_map/mask_fault_bounded --widths 40 600 --depths 3 2049 --fault mask
python3 verification/sram_storage_map/test_formal_audit.py
python3 -O verification/sram_storage_map/test_formal_audit.py
```

The checker prints a deterministic JSON coverage summary and `AUDIT PASS` or exits
nonzero with `AUDIT FAIL`. It writes no evidence files; graph replays use
temporary directories. Elapsed audit time goes separately to stderr. Redirect
stdout if a persistent semantic audit report is needed; ordinary and `-O`
stdout reports can be compared byte for byte.
The tests print unittest results and remove their temporary evidence copies.
`SRAM_AUDIT_FIXTURE` can select another completed healthy stage containing
`w40_d2049`. Next audit both complete matrix stages, then combine the mapping
theorem with the SRAM behavior and the already proved FIFO contract.

## Evidence checked

1. The two current dependency files must match SHA-256 identities pinned in the
   independently reviewed checker, and the manifest must agree. A candidate
   manifest cannot authorize replacement source by declaring a new hash.
   Snapshot bytes must exactly match those files, except for the explicitly
   requested, independently enumerated data/mask/bank fault patch. The runner
   snapshot must match a pinned reviewed runner SHA-256 for its declared
   reference profile. Historical evidence remains bound to its historical
   runner, even after adding the reviewed bank-captured reference. Wrapper ports, common clock,
   logical width/depth, address width, and depth-one physical depth of two are
   checked separately.
2. Independent geometry selects `(rows, bits)` as `(256,32)`, `(512,64)`,
   `(1024,128)`, or `(2048,256)`, with depth banks and width lanes rounded up.
   Every expected bank/lane position must exist exactly once. All nine macro
   pins, their directions and widths, and the fixed macro class are checked.
   Every Q bit must be an integer wire distinct from every other Q bit and
   every primary input. Macro clocks and surviving sequential clocks must be
   the original common positive-edge clock.
3. Starting from the original graph, the checker independently removes only
   the actual macro cells and adds Q inputs plus observations of the eight
   original macro input pins. Exact whole-JSON comparison checks every module,
   cell, parameter, connection, port, net, and attribute. Additional internal
   state cuts, omitted macro observations, altered clocks, or hidden graph edits
   therefore fail. Independent re-elaboration of source snapshots and the
   reviewed wrapper must reproduce `original.json` exactly.
4. The property file must match a closed, independently authored contract.
   WCS/RCS compare the full address divided by macro depth with the actual bank;
   WA/RA compare the full address modulo macro depth. D checks all physical
   bits, including zero padding in the last lane; WM checks every byte mask
   bit as one. Both clock pins are checked in a single assertion. The full
   logical output word concatenates every lane in its own bank and selects the
   bank remembered from the last issued read. The `captured_address` profile
   uses one complete-word dynamic selection assertion. The `captured_bank`
   profile uses one complete-word assertion for every possible physical bank,
   each enabled by `seen && last_bank == bank`. No bitwise sampling is used.
   Extra assumptions, omitted assertions, changed initialization, extra
   procedural code, or weakened guards are rejected.
5. `prepare.ys` and `proof.ys` must be exact reviewed commands. The healthy
   query is `sat -seq 2 -tempinduct -maxsteps 8 -prove-asserts -verify
   -show-inputs -dump_json ...`; fault controls use bounded `-seq 4` without
   temporal induction. The graph after property elaboration and optimization
   is independently regenerated and must exactly match `proof.json`. The
   bank-captured profile explicitly runs `wreduce` then `opt -full -keepdc`;
   the original profile retains `opt -keepdc`. These are solver preparation
   optimizations after preserving and checking the complete original/cut graph.
   Explicit `--bit-lower` additionally requires manifest `bit_lower: true` and
   exactly `techmap` followed by `opt -full -keepdc`; that resulting gate graph
   is independently replayed as well. Default evidence may not silently use
   this extra transformation.
   No
   `$assume` is permitted. Its only initialization attribute is `seen = 0`.
6. Healthy evidence needs a successful elaboration, successful solver status,
   an actual base-case success line and induction-success line, imported
   assertions, the `seen` initialization, and unconstrained input equations.
   A failed candidate induction alone is not a reachable bug; it can precede
   a successful longer induction. Negative controls instead require exit 1,
   `SAT proof finished - model found: FAIL!`, the expected `-verify` failure,
   and a nonempty generated witness. Result flags and counts must agree with
   this evidence; they cannot replace it.

Eight input-pin obligations per macro are expressed in seven source assertions
because WCLK and RCLK share an assertion. There is one complete output-word
assertion per configuration in the address profile, or one per bank in the
bank-captured profile. Optimization folds or merges many identical
assertions; the optimized `$assert` count is not the source coverage denominator.

## Temporal and address scope

The ghost state executes `if (i_read_cs)` on each positive clock edge. It records
that issued address and assigns `seen` to `i_read_addr < logical_depth`.
Consequently, the output obligation is enabled when the **most recent issued
read is legal**. It continues through stalls and writes until another issued
read. An illegal read disables this output obligation until a later legal read;
the proof does not promise to retain the previous legal word across an illegal
read. Before the first legal read the output is unspecified. `last_read` and
the actual bank register have no imposed initialization, and `seen` starts at
zero only to exclude pre-read data. Unrestricted inputs permit a legal read
immediately; the guard cannot remain permanently false by assumption.

The bank-captured reference instead records the quotient
`i_read_addr / macro_rows` in `ceil(log2(banks))` bits, with a minimum width of
one bit. When `seen` is true, the last issued address was less than logical
depth, so this quotient is less than `banks` and fits without truncation.
There is exactly one matching bank guard and its assertion checks every
logical output bit. On a stall, both references retain the same selected bank;
on a legal read, both select the quotient of that read; on an illegal read,
both disable output checking. Initial ghost-bank values are unconstrained and
irrelevant while `seen` is zero. These facts establish the same temporal
output contract for the two reference profiles. No extra input assumption or
actual-mapper cut is introduced by storing only the quotient.

No address or enable is assumed legal. Macro pin obligations apply to every
represented input address, including an address outside logical depth, unused
rows of a final bank, and encodable nonexistent banks. There is no requirement
here to suppress a logically illegal access to a physically present row.
Address legality belongs to the separate FIFO invariant and its composition
with this mapper. The explicit wrapper address width is `depth.bit_length()`;
at power-of-two depths it intentionally includes an extra address bit. Depth
one elaborates physical depth two while the output legality check remains
against logical depth one.

The solver uses Yosys Boolean SAT semantics. This proof does not establish
four-state X/Z behavior, unknown-address simulation semantics, analog clock
behavior, or metastability protection. Dynamic selects outside existing banks
can produce undefined values; the output guard excludes such a latest read
from its data obligation. The unguarded pin checks remain in force.

Each macro Q word is an independent arbitrary symbolic input at every proof
step. This makes lane and bank selection universal over all possible words,
but it does not constrain Q to a past write, enforce registered latency, prove
Q holds through a stall, or check read-during-write behavior. Those are separate
actual macro behavior and simulation obligations. The held-bank theorem selects
the currently supplied Q word of the remembered bank; a held data word requires
the SRAM behavior contract as well.

## Independence and remaining trust

The geometry and semantic contract above were reviewed directly against the
source: bank select is quotient, row address is remainder, width padding is
zero, masks are all ones, and bank state updates only on issued reads. The
checker implementation is separate from the generator. Its closed property
template deliberately shares the proof's reviewed syntax and signal vocabulary;
exact template agreement is a structural consistency check, not a second
independent mathematical specification by itself. The semantic review in this
document and source-to-graph replay are the additional checks.

Graph replay uses the same installed Yosys frontend and optimization engine,
not an independent compiler or solver. The checker does not rerun SAT or
validate a solver proof certificate. It checks existing solver logs and exit
status against the validated scripts and graphs. It detects missing, corrupted,
or weakened evidence, but does not authenticate logs against a deliberately
forged successful solver run. Dependency access and the same Yosys version are
required for reproducible exact graph comparison. Whitespace is the only
ignored difference in wrapper/property text; an intentional proof-format
change needs renewed review and a checker update.

## Actual fixture validation

The following independent audits were executed during this review:

| Stage | Configurations | Macro instances | Graph replays | Audit result |
|---|---:|---:|---:|---|
| `first_healthy` | 4 | 24 | 8 | Passed, including base and induction logs |
| `data_fault_bounded` | 1 | 2 | 2 | Passed audit of reachable SAT failure |
| `bank_fault_bounded` | 1 | 2 | 2 | Passed audit of reachable SAT failure |
| `mask_fault_bounded` | 4 | 29 | 8 | Passed audit of reachable SAT failures |

Observed audit runtimes were approximately 0.63, 0.08, 0.11, and 0.71 seconds
respectively on the local toolchain; these are audit costs, not proof runtimes.

The 23-test suite uses copies of the actual healthy `w40_d2049` source,
graphs, properties, commands, and logs. Its acceptance case runs both graph
replays. Rejected perturbations cover missing macros; aliased Q bits; internal
state cuts; added source or graph assumptions; missing/disabled complete-word
assertions; missing output bits and mask assertions; current-address selection
instead of held bank; `seen` permanently zero; incomplete requested parameter
coverage; missing wrapper parameters; hidden SAT constraints; missing base-case
evidence; modified source snapshots; self-declared replacement dependencies;
extra state initialization; altered
original and cut graphs together; and missing proof-graph assertions. The
optimized Python invocation propagates `-O` to checker subprocesses, so these
checks do not silently disappear when Python assertions are disabled.

The additional reference-profile test transforms the actual reviewed property
artifact into the two-bank quotient form, accepts complete coverage, and
rejects a missing bank assertion or current-address bank selection. Another
test rejects excluding a successful configuration from a claimed incomplete
stage, and a third rejects undeclared bit-level lowering. The actual
new-profile bank-source mutation also produced a reachable
SAT counterexample and passed normal/optimized evidence auditing; its two
full-word bank obligations bring that case to 16 source assertions.

The expanded matrix has six widths `8, 32, 40, 256, 512, 600` and sixteen
depths `1, 2, 3, 5, 255, 256, 257, 511, 512, 513, 1024, 1025, 2048, 2049,
4097, 65535`, totaling 96 exact configurations. The original address-reference
runs proved 94 configurations; `(512,65535)` and `(600,65535)` each timed out
at the 120-second solver limit and remain preserved as unproven in
`mapped_wide_widths/results.json`. The subsequent `captured_bank_max` attempt
is also retained separately and is not counted as final evidence.

`--allow-incomplete-stage --exclude-config 512:65535 600:65535` audits the
46 successful wide cases while requiring exactly those failed result rows,
explicit timeout exit 124, no proof-success flags, and an incomplete stage.
It reports the excluded pairs as `timeout_unproven`; exclusions cannot shrink
the requested Cartesian denominator silently, hide a successful case, or turn
a timeout into a proof. The 48 small and 46 wide audit summaries are
byte-identical between normal and optimized Python. They cover 156 and 420
macro instances respectively, with 96 and 92 graph replays. Their normal/
optimized runtimes on the final checker were 7.444/7.088 and
10.874/10.649 seconds.

Audits are retained under
`build/verification/sram_storage_map/formal_audit_reports/`; semantic reports
use `_normal.txt` and `_optimized.txt`, while elapsed time is in the separate
`.timing.txt` files. The two formerly timed-out geometries are independently
rerun under the equivalent bank-captured profile in `bank_obligations_max`.
Its final evidence is reported separately from the original timeout records.
The width-512 bank-captured case proved base and induction in 76.180 seconds;
normal and optimized audits both passed and produced identical semantic
reports, taking 3.165 and 2.989 seconds. Width 600 timed out again while solving
induction step two, at 120.258 seconds. The additional `bank_bits_max` width-600
attempt, with explicit bit-level lowering, timed out at 120.040 seconds in
`techmap` preprocessing, before reaching SAT. It produced no proof and is not
counted as an audited successful configuration. All six failed attempts across
the four historical stages are preserved in the final summary with their
separate phases and log paths.

Thus the final independently audited union has 95 distinct configurations,
640 actual macro instances, 190 source/property graph replays, and no added
input assumptions. All accepted semantic reports, including the new bank-source
fault control, are byte-identical between ordinary and optimized Python.
The 600-by-65535 case remains an explicit formal gap; it does not block the
separate endpoint transaction work and must not be reported as a counterexample
or as a proof. The additional bit-lowering checker path was reviewed and its
declaration mismatch tested, but no successful bit-lowered graph audit is
claimed because that run timed out before emitting its final proof graph.
Direct comparison of `original.json` and `cut.json` for both largest
geometries found the graphs identical between the original and bank-captured
stages after normalizing only their stage-directory paths; this evidence is
retained in `profile_graph_comparison.json`.
Passing any finite matrix also does not prove every other supported parameter
combination. Storage-wrapper composition, content semantics, technology timing,
physical implementation, and endpoint transaction behavior remain distinct
requirements.

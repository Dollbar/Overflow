# 信用累积与实际FC发布计划

目标：把已退休的20槽信用向量变成真实32位FC字段，以及全部初始FC实际发送后才可发送的Initial Credit Release Complete消息。依据Common2.0 §5.8及Table5-26；此模块输出可停顿本地发布提议，不绕过Tx实际半Flit分类位置。

架构：一次合法start采样20×WIDTH容量及shared模式，20个WIDTH+1 pending计数包含已被输出提议预约但尚未发送的信用。每个FC的四类分别按五个Pool/VC槽轮转选择，CMD每类最多7，Data每类最多31。32位FC寄存，valid未taken期间字段/类别/共享标志保持；只在实际发送FC后减pending并推进轮转。正常release来自实际FIFO退休，仅初始完成消息taken之后接纳；每槽4位增量，旧pending+增量超本地累积计数上限时反压，不借用同拍发布空间。共享模式保留原始逻辑类别发布，接收方再合并Data Pool；计数扩一位容纳共享容量全部返回同一类别。

本地契约：WIDTH1..16，start在inactive接纳一次；非共享配置RequestData和ResponseData各至少一个非零槽。复位取消全部未发送提议和局部状态，上层必须按链路复位契约联动对端。发送端将FC放入合法Control槽，将完成指示组成MSG1，只有实际端口taken才能确认publisher提议。当前轮转选择实现允许FC之间一个装载空拍，吞吐优化以后需另行测量和证明。

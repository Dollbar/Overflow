# 完整协议核的交付范围、指标与阶段计划

日期：2026-09-07。状态：详细计划草案，待规范问题关闭和 profile 审批，不是已冻结规范、已实现功能或已测性能。依据：正文研读（历史文档已清理）、机制补充（历史文档已清理）、[疑点与依赖](specification_issues.md)。

## 1. 最终交付是什么

建议交付 **UALink 数字协议 RTL IP 套件 + 可执行参考模型 + 验证环境 + 管理参考软件 + 集成/签核资料**。不是一个单独收发模块，也不是已经流片的 ASIC、GDS、交换机成品或完整 NPU。

| 交付单元 | 职责 | 边界 |
| --- | --- | --- |
| Endpoint IP | 原生 UPLI originator/completer、事务与顺序、TL、DL、错误处理、端口/station 控制 | 集成到加速器；不实现 NPU 计算/HBM 控制器，也不擅自定义上层内存原子语义 |
| Switch IP | 消息拆分、路由、重打包、信用/缓冲、无饥饿仲裁、vPod 隔离、INC | 面向单级逻辑交换平面；内部可做分层仲裁，不增加不受支持的外部交换机级联 |
| Shared station/digital PHY IP | DL、CRC/LLR、控制/UART、RS/PCS/FEC、对齐、速率匹配及数字 PHY 适配 | 数字 FEC/PCS 纳入完整目标；模拟 SerDes/CDR/PLL/均衡、封装通道为外部 IP/平台输入 |
| Security IP | GCM/KMAC、上下文、换钥、计数器、PCRC、可信配置接口 | 仅密码核不等于完整系统安全；RoT/TEE、证明、密钥注入与保护由平台集成 |
| Management support | CSR、能力、状态、计数器、错误快照、中断与固件接口 | SMA/NMA/Pod Controller 的网络服务在软件运行；CPER 持久化需平台存储 |
| Models and VIP | 功能/周期模型、独立 scoreboard、驱动/监视器、错误注入、断言和覆盖 | 自研 VIP 回归与第三方互操作分别标记，不能互相替代 |
| Integration/release kit | 文件清单、接口手册、依赖锁定、回归与报告入口、平台绑定、签核矩阵 | PDK/lib/商业模型和规范全文不得默认打包；源代码许可证另行审批 |

可综合核心按 Verilog-2001 `.v` 规划；仿真 VIP、断言和 testbench 可用 SystemVerilog `.sv`。公共常量/类型定义与寄存器描述只允许一份权威来源，模型/VIP 需要独立检查而非共享全部编解码实现。原生 UPLI 是对外协议集成接口；AXI/NoC 桥如需提供，作为单独本地适配器，不冒充标准接口。

## 2. 提议冻结的功能 profile

协议版本锁定 Common 2.0 + 200G DL/PL 2.0 + Manageability 1.0；所有修订号写在内容/清单中，不写进工程源文件名。128G DL/PL 与 chiplet 规范属于另一个工作范围，暂不纳入。

| 功能族 | 最终目标 | 必须说明的条件 |
| --- | --- | --- |
| 端点和路由 | 10-bit Accelerator ID 全合法空间；直连与 Accelerator—Switch—Accelerator；多平面；不规则有效成员 | ID 能表示 1024 个 Accelerator 不等于一个具体芯片有 1024 个物理端口 |
| 事务 | Read/Write/WriteFull、协议规定 Atomic 传输、响应/错误、合法消息及保留编码处理 | 普通 Atomic 本地操作定义和一致性责任需与加速器接口契约冻结 |
| TL | 四 VC、四类信用及池、SO/SOL/non-SO 合法组合、压缩/非压缩、共享数据池能力 | 能力协商、互斥/条件配置列出合法矩阵；不能把保留值当扩展能力 |
| DL/PHY | 100G/200G 路径、x1/x2/x4、CRC/LLR、控制/UART、数字 PCS/FEC | 交换角色满足全部 bifurcation 要求；选择 optional 后满足全部条件要求 |
| 时钟/速率控制 | 用户已批准实现 Accelerator UPLI 调频、两阶段速率通告与 Tx pacing；Switch 固定 UPLI 速率 | 独立于 PHY 线速/CDR；最低参考速率、消息时限、跨域缓冲与多 station 共享时钟影响域按 §2.2 验收 |
| 可选链路增强 | Resiliency、Folding、所选 200G 路径允许的低时延 FEC interleaving | 逐个合法组合实现和验证，不支持的组合在配置/协商时明确处理 |
| INC | 完整 primitives + 完整 block collectives 档位 | 包含完整标准算子/类型矩阵、资源生命周期、错误及数值语义；不是只有一个 AllReduce 演示 |
| 安全 | 明文、仅加密、加密+完整性合法模式，PCRC、完整换钥与 INC 安全域 | 必须先关闭安全字段疑点；密码学算法验证、协议验证、平台安全分开 |
| 管理 | 规定的发现/配置/隔离/重连/遥测/RAS，配套管理软件和驱动参考 | 路由对象先选一种合法组织方式；管理 schema 必须与官方配套资产对齐 |

这里选择实现多项 optional，是为了满足用户的完整工程目标，不意味着标准要求每个端点无条件具备所有选项。最小端点闭环仅为中间里程碑，不能作为最终完整版本交付。其他舍入模式若采用规范允许的 RNE 回退，必须在能力与验证说明中明示，不冒称全部原生舍入模式。

交叉审查补充：Common §2.4 p37 的部署要求是 Pod 内 station 使用相同 bifurcation、Accelerator 端口数相等；设备支持 x1/x2/x4 不自动授权同一 Pod 任意混搭。管理 PortNum 为 uint16，DL 端口字段为 12-bit，端点间 IV 源端口及 INC 安全身份描述为 10-bit，端点间 KMAC context 又使用 16-bit 源端口填充表示；范围校验与配置限制单列，不能隐式截断。见 [审查决定](review_decisions.md)。

### 2.1 多 station 与 bifurcation 参数化约束（用户已批准纳入计划）

本节固定参数化方向与验收约束，不表示 RTL 已实现或任何物理规模已签核。机器可读约束见 [工程配置](../config/project.json) 的 `station_parameterization`。以下参数名是本工程接口契约，不是新定义的 UALink 线上字段或官方管理枚举。

| 参数 | 含义与阶段 | 约束 |
| --- | --- | --- |
| `NUM_STATIONS` | 一个 Endpoint 或 Physical Switch IP 顶层内的物理 station 实例数；综合展开参数 | 正整数，支持非二次幂；端点与交换顶层分别配置；不等于 Accelerator 数量或单卡 NPU 数量 |
| `STATION_BIFURCATION` | station 的端口划分：`x4`、`2x2`、`4x1`；作为实例初始配置参数，并纳入受控管理重配置契约 | 对应每 station 1/2/4 个端口及每端口 4/2/1 条 lane；不允许用初始模式裁掉交换角色必选的三模式能力 |

`LANES_PER_STATION=4` 是固定规范约束，不开放为任意 x8/x16 station。`NUM_LANES=4×NUM_STATIONS`、`PORTS_PER_STATION` 和 `NUM_PORTS=NUM_STATIONS×PORTS_PER_STATION` 均为派生量，不提供互相矛盾的独立输入。多个 station 是多个链路/端口的聚合，不是将单条 UALink 链路扩大到 x8/x16，也不默认允许事务任意跨 station 条带化。

依据 Manageability 1.0 §1.4、Table 1-1 p16，每个 Accelerator 和每个 Physical Switch 的端口数量均不超过 1024。因此，对所有 station 全量配置的某一模式，至少检查：

`NUM_STATIONS × PORTS_PER_STATION ≤ 1024`

上限性质：这是 Manageability 1.0 对其管理的 UALink Pod 明确规定的规模限制，属于本工程当前配套规范组合必须满足的要求，不是本项目自行选择的性能目标；依据不是 DL 的 12-bit 端口字段或管理 uint16 表示宽度。超出后不能继续声明符合这一完整管理基线，必须另行确认适用规范/范围，不能仅改 RTL 参数便宣称标准允许。它也不表示 Common/TL/DL 所有字段具有同一个 1024 的编码上限。

| 模式 | 每 station 端口数 | 仅由端口数量约束推导的 station 上界 |
| --- | ---: | ---: |
| x4 | 1 | 1024 |
| 2x2 | 2 | 512 |
| 4x1 | 4 | 256 |

上表是模式相关的算术上界，不是完整 profile 的合法性或已实现容量证明。若同一实例规模要在三种模式下均能全量配置，则须满足 `4×NUM_STATIONS≤1024`，即不超过 256。交换角色仍满足 C §9.2 p246 的全部 bifurcation 能力要求；不能将 1024-station/x4 的算术结果当作完整交换 IP 已合法、再静默移除其它必选模式。端口计数不能仅统计 link-up 的端口，以关闭链路掩盖超限。

实施时还必须满足以下计划约束：

- 配置合法性分层判定：参数类型/派生量 → 每个设备的端口数量 → 角色及模式能力 → Pod 一致性/拓扑 → 安全身份映射 → 已验证发布配置。任何一层通过都不能代替后续检查；非法静态配置在生成/展开前报错，非法管理配置不得生效，不伪造标准线上错误码。
- Pod 中所有 station 按 C §2.4 p37 使用一致 bifurcation，各 Accelerator 的端口数相等；不要求 Accelerator 与 Physical Switch 的 `NUM_STATIONS` 相等，也不强行要求不同 Physical Switch 大小相等。拓扑/路由容量另行检查。
- station 内的 2-bit PortID、设备级 PortNum、内部 station 索引分别处理。内部索引宽度按实例数推导，单实例避免零位宽；非二次幂的未用索引不能被别名化。不得以简单拼接或截断代替尚待冻结的安全/管理 PortNum 映射（A13/R029）。
- 三种模式能力与本次选中的运行模式分开公布。模式改变不是带流量的组合选择器：计划采用受控停发、排空或规范恢复/复位流程，更新端口清单、路由/信用/压缩/安全上下文及邻居验证后再使能；精确顺序在 G1 按适用条款冻结，不承诺热切换无损，也不无条件清零仍使用旧密钥的安全计数器。
- Endpoint 按 station 提供原生 UPLI 集成边界；上层聚合接口若共享，必须明确注入/接收能力与调度/顺序边界。TL/DL 信用、LLR、错误状态及安全上下文按规定的端口/流维度隔离，物理缓存或计算资源可以共享但必须证明账户不串扰；不把可共享的实现资源误说成标准要求全部复制。
- 带宽、缓存、仲裁、INC 和安全处理预算随配置重算。200G/lane、四条 lane 全量工作的每个 station 单向标称容量仍为 100 GB/s，bifurcation 只划分端口，不凭空增加总带宽；实际 payload 吞吐及拥塞损失另测。
- 发布清单逐项列出数量、模式、角色、协议 profile 和工具/平台证据。16 不作为规范上限；1024/512/256 不作为已综合或已签核规模。具体默认实例数、已验证最大值和平台资源上限仍待 G1/G7/G8 冻结，不新增对物理可实现性的承诺。

### 2.2 UPLI 调频与跨层速率控制（用户已批准纳入计划）

完整实施与测试契约见 [时钟与速率计划](clock_and_rate_plan.md)，机器可读状态见 `config/project.json.clock_and_rate_control`。默认→参考时钟→新 PLL 频率的过程必须包含两次 TL Rate Notification 与 ACK：先获得参考速率 ACK 才能降至参考时钟，切到新频率后再通知并等待 ACK。对端先使必要的 pacing 生效，再于收到请求后 1 μs 内回复；不是在 UPLI 停钟期间盲等恢复。

UPLI 是本地同步接口，双方时钟共同切换；DL/PHY 维持其适用物理节奏，不能将 UPLI 降频误接成 SerDes 波特率降低。速率值按 x4/x2/x1 每链路的 512/256/128-bit 基准归一化，不直接抄任意本地总线时钟。多个端口共享可变 UPLI 域时，全部受影响活动链路的适用握手完成条件必须统一控制。

补入独立工作包：时钟/PLL 适配与速率控制、DL Basic 消息调度、Tx pacing、跨域 FIFO、控制时限与 CSR/事件、各频点 STA/CDC/RDC。它们先在 G1 建立模型和契约，G2/G3 做端点/交换闭环；PLL/MUX/SerDes 库与真实频点属于待确认的平台输入。不得将 UPLI ClkReq/ClkAck 当作调频开关，也不得把空载 payload flit 全部改成 NOP。

### 2.3 手册增量缺项纳入

缺项与验收细化表（历史文档已清理） 的 R046–R077 纳入本计划：除了调频，还包含 Basic/Control/UART 并发和数值时限、Folding 热保护/Tx Ready、DL 状态计数与错误隔离、PCS rate matching、TL catch budget/信用更新、U-turn 和独立路由表、管理时间戳/资源树/API 及 teardown。部分主题以前已有，现在补足独立判据；不是将所有内容都视作新功能。

强制、条件强制、推荐与工程增强保持区分；非 chiplet Rx 背压防护为拟选增强，管理 gNMI/Redfish 的 mTLS 级别按各自条款，不将其统一写成相同强制要求。旧规范疑点和外部资产门槛继续保留。

后续事务/恢复审计新增 R078–R100，详见 事务与恢复计划（历史文档已清理）：两种读响应模式、Tag/顺序、自然 byte lane、Drop/Isolation 与 link-down 的信用/作用域、INC 和 Block 完成/队列/地址生命周期。R097 的 drain-only 结束流程受 A18 阻塞，不能提前冻结；F16 的主要规范来源纠正为 C §6.3–6.4。

开工条件审计进一步新增 R101–R110：DL CRC/两级消息仲裁、reserved 字段与 op 的分类、LLR 歧义/显式序号调度、请求压缩缓存索引/资格/旁路/失效，以及方向连接信用。详见 开工条件（历史文档已清理），这些也是待验证判据。

### 2.4 UART 保留接口、自定义消息协议暂缓

按用户本轮决定，保留标准带内 UART 的固件不透明 DWORD TX/RX、状态及复位/错误接口边界；R058/R059 的标准传输、信用及 reset 仍纳入计划。暂不定义厂商 Vendor ID、命令编号、诊断格式或私有安全消息；不增加外部串口引脚。接口信号/CSR 尚未冻结，也尚无 RTL。

若以后使用 Vendor Defined Packet，其首 DWORD 的 TLV 前缀与跨 transport message 规则遵循 L §2.4.4.1.4 p38；暂缓的是其上自定义语义，不是重新设计这一标准前缀。Basic Rate Notification 和标准安全/管理功能不随本项推迟或移入 UART。详见 范围与验证边界（历史文档已清理） §1。

## 3. 量化目标与测量边界

以下带宽为十进制单位，Gb/s 为 bit/s，GB/s 和 TB/s 为 byte/s。

### 3.1 标准约束与理论容量

| 项目 | 预算/约束 | 性质及依据 |
| --- | --- | --- |
| 单 lane | 200 Gb/s 标称；212.5 Gb/s 物理串行速率 | L §3，两个层次的数值，不能相加或互换 |
| 一个 x4 station | 单向 800 Gb/s = 100 GB/s；双向相加 200 GB/s | 四 lane 标称预算，不是实测 payload |
| 多 station 加速器 | 配置 S 个这样的 station：单向 S×100 GB/s | 已批准数量/模式参数化，见 §2.1；S 仍受端口数、profile、注入/内存能力及物理资源限制，已验证上限未冻结 |
| 示例：128 个加速器，每个一个 x4 端口 | 全域单向端口注入容量 12.8 TB/s | 128×100 GB/s；单平面共 512 lanes，非 128 lanes |
| 上例均分 64/64 | 单向二分容量设计预算 6.4 TB/s | 64×100 GB/s；只有交换内部及缓存调度支持无阻塞跨半区传输时才成立 |
| TL 打包上限示例 | 压缩长 WriteFull 95.238%；带认证对应示例 88.889% | C §5.4 特定对称流量，未扣 DL/PHY 等开销 |
| LLR 未确认窗口 | 最多 255 个 DL flit | L §2.6；扩大 SRAM 不改变协议窗口 |
| 部分 DL 控制时限 | Rate ACK 1 μs；适用 Control pending 后 10 ms 重启；UART reset 无 SUCCESS 10 ms 重试 | L §2.4–2.5，必须按具体消息/状态适用，不是统一 RTT 或完整调频目标 |

Replay 容量例算：若为保守预算取发送 DL 数据速率 R=100 GB/s、ACK 往返时间 T=1 μs、每 flit=640 bytes，则 ceil(R×T/640)=157 个 flit，尚需考虑实现流水和 ACK 抖动余量。可评估物理 256 槽、协议最多 255 个未确认的方案；256×640=160 KiB 数据存储，另计 ECC/元数据。255 个窗口在这个 R 下只覆盖约 1.632 μs，不能承诺任意距离/RTT 仍满速。具体缓存深度在模型扫描后冻结，不把该例算当已选 SRAM。

上例的 1 μs 是假设的 LLR RTT，不来自 Rate Notification 的 ACK 时限。L §2.6.7 p55–56 定义 RTT=ACK latency+release latency+2×channel latency，其中前两项按封装管脚界面测量；channel 预算含线缆和适用 retimer。报告分别给出组成项，数字模型未绑定 PHY 时不能冒充 pin-to-pin 实测。LLR watchdog 默认 10.24 ms 按 flit-time 计数，亦不是 TL Rate ACK 的 1 μs。

数字内部数据宽度与时钟共同满足速率预算。512 bits×1.5625 GHz=800 Gb/s 是归一化算术关系；不要求全芯片都运行在 1.5625 GHz，也不允许通过加宽本地总线而改变原生 UPLI 外部时序语义。数字 PHY 接口参考另见 L informative 附录 B。

STA 计划至少分开默认 UPLI 0.640 ns、参考 UPLI 6.400 ns、最终已选工作频点及 DL/PHY/恢复域；Switch 固定模式单列。频点切换、PLL lock、时钟 MUX 与 CDC/RDC 不由单一 setup/hold 报告替代。时钟和时限约束详见 [专项 §4](clock_and_rate_plan.md)。

### 3.2 工程验收目标（拟定，尚未实测）

| 项目 | 拟定标准 | 测量条件 |
| --- | --- | --- |
| 完整性 | 选定 profile 的全部适用强制/条件条款 100% 映射并有通过证据 | 每项追溯到修订版、角色、模型、RTL、测试/断言和结果；未决强制项不能豁免为已完成 |
| 长消息吞吐 | 基线无拥塞场景达到该场景独立计算 payload 上限的至少 95% | 256-byte 合法长读/WriteFull、双向均衡、充足信用、声明 RTT、无注错；压缩冷热、安全开关分别测；上限扣除全部已知开销并经独立复核 |
| 压力吞吐 | 输出性能曲线而非统一一个“线速率”百分数 | 负载 10/50/80/95/100%，读写混合、小包、热点、incast/outcast、AllToAll(v)、INC；记录瓶颈和可解释的上下界 |
| 延迟 | 报告 p50/p95/p99、各层时间与最坏持续背压情形 | 分开 UPLI→UPLI、数字链路、pin-to-pin；后者需真实 PHY 时延模型/平台 |
| 交换延迟参考 | 对满足规模/配置条件的实现，争取 C §9.9 的 <200/<250/<300 ns 建议 | 分别对应 128/256/512 lanes、64-byte Write、x4、启用 FEC、无负载等原文条件；不是未选工艺前的签核承诺 |
| INC 性能 | 每个算子/精度/成员数给出服务率、资源数、排队和输出放大预算 | 输入带宽与输出带宽不同；不能以一个整数加法器吞吐代表 FP64/FP8 全矩阵 |
| 功能覆盖 | 冻结后的合法功能 bins 100%，条件非法/错误路径单列 | 不把禁止组合算未覆盖；不能删除困难场景达到数值 |
| 代码覆盖 | line/branch 各 ≥95% 作为初始门槛，所有缺口审核；关键安全/恢复 FSM 可达状态及转移全覆盖 | toggle 单列；工具、分母、排除项、配置和种子必须记录；代码覆盖不替代功能证明 |
| 形式与静态 | 无未审查严重 lint/CDC/RDC/断言失败；信用守恒、无溢出、tag/上下文关联、合法顺序和安全计数器有证明/边界证据 | 无死锁/前进性证明声明规模、环境公平假设与有界/无界范围，不以 bounded pass 冒充无限规模证明 |
| 时序/物理 | 已选目标全部签核角 setup/hold、约束完整性、时钟/复位交叉通过 | 工艺、时钟、lib、SRAM/SerDes 模型与角点待确认；不沿用 KDLink 的 TSMC 28 nm 或 1 GHz 成绩 |
| 管理恢复 | Controller/SMA/NMA 重启不单独破坏既有工作负载；CPER 跨重启保留 | 与设备/持久链路故障导致 workload 失败的规范流程分开测试 |

## 4. 测试矩阵和规模证据

规模集合建议：1、2、3、4、5、7、8、15、16、31、32、33、63、64、65、127、128、129、255、256、257、511、512、513、1023、1024。

- 1 个 Accelerator 验证配置/隔离和允许的本地路径，不能强发要求至少两个参与者的 block collective。
- 小规模 2/4/8：端点、交换、DL、数字 PHY 全栈 RTL 闭环及密集注错。
- 中规模至 128：参数展开检查、资源/路由 RTL 仿真逐档扩展；性能模型必须由小规模 RTL 校准。是否进行每档所有 SerDes lane 的全栈同时仿真取决于工具与资源，报告不能混称。
- 256–1024：完整 ID 空间/路由/成员/队列模型与局部 RTL 边界验证先行；若交付宣称某个该规模物理 switch configuration 已签核，必须补该配置的实际 RTL/综合/时序证据。模型容量不冒充全规模芯片实现。
- 对每个规模做有效成员稀疏化、重编号、ID 上界、空 group、非法 group、vPod 交叉隔离。端点数量不是必须填满连续成员的要求。
- 事务交叉维度：合法命令×长度/对齐×字节使能×VC/pool×端口×顺序×安全/压缩；复杂组合采用有说明的 pairwise/风险定向方法，关键关联用完整交叉，不能宣称全部笛卡尔积都跑过。
- 链路维度：合法速度/宽度/FEC 组合、reset/online/offline、CRC/FEC 可纠正/不可纠正、ACK 延迟/丢失、环回、replay 窗口满、fold/unfold、对齐丢失与恢复。
- 安全维度：三流换钥、计数器边界、密钥过期、认证失败、poison、SOL VC、block/普通响应类型、安全域隔离、reset 与迟到消息。敏感密钥不得写入公开日志。
- INC 维度：完整数值矩阵、NaN 等边界、固定参与者确定性、宽精度输出、stride/address 溢出、queue 满、部分完成失败、撤销/排空、普通业务竞争。
- 管理维度：配置/运行状态分离、邻居不匹配、路由更新、vPod 建立/删除、进程重启、设备故障、持久日志、访问权限、TLS/mTLS 与 key/route LOCK。

每份报告必须标记 `semantic_model / cycle_model / unit_rtl / integrated_rtl / digital_phy / analog_model / synthesis_sta / independent_interop`；同一测试名不代表同一证据层级。

### 4.1 多 station 专项矩阵（计划，未运行）

此处 station 数量与上文 Accelerator 数量是两个独立维度。先按 §2.1 完成组合分类，再选择 RTL 配置，不盲目展开完整规模的全栈仿真。

- 数量集合：1、2、3、4、5、8、15、16、17、31、32、33、63、64、65、255、256、257、511、512、513、1023、1024、1025；另测 0、负数、非整数及未知模式。单实例位宽与 3/5/17/33 等非二次幂索引必须专项覆盖。
- 模式交叉：每个数量与 x4/2x2/4x1 交叉检查 lane/port 推导、最后合法端口、非法尾索引。数量约束边界分别为 x4 的 1024/1025、2x2 的 512/513、4x1 的 256/257。以 257 个 station 为例，x4/2x2 只通过本项端口数量检查，4x1 不通过；宣称三模式全量配置的 profile 仍不通过。
- 部署/管理：同 Pod 模式不一致、Accelerator 端口数不等、合法但端点/交换 station 数不同、非法/未获支持的重配置、模式切换后 Operational Ports 重查；错误配置不得部分生效。
- 功能/性能：小规模多 station 并发收发、三种模式、单路与全路饱和、局部背压/重放/复位及故障传播范围；检查信用守恒、顺序、Tag/安全上下文和共享资源串扰，不能强加“所有故障都只影响一个 station”的承诺。
- 证据分层：全候选范围先做配置/算术检查；功能 RTL、集成 RTL、吞吐与综合/STA 分别列明实际跑过的配置。性能报告说明上层注入、交换出口、安全/INC、缓存及 PHY 哪一项限制聚合吞吐。

时钟/速率的 G1 交付须同时给出频率/位宽归一化、各计时器单位、Basic/Control/UART 最坏调度、共享时钟影响域、PLL/MUX 平台接口和 FIFO 在途预算；未确认正常调频无溢出及时限前不得进入对应 RTL。G2/G3 运行双向业务中的调频握手，G6 联合真实数字 PHY/FEC/Folding，G7/G8 对各已发布配置记录降速及恢复性能与多模式 STA 证据。

事务/恢复的 G1 同时交付独立身份/beat 完成和顺序模型、信用账本、RAS 状态与 Block 队列/地址/状态缓冲区契约；G2/G3 验证普通事务和故障隔离，G4 集成 INC 完成与资源回收，G5 复核响应类别和本地控制的安全边界，G6 联合软件恢复。不能把 Link Down 实现为全局 UPLI reset，也不能将 Invoke OKAY 当成最终 Collective 完成。

目前不按页数估算开发天数：完整浮点 INC、数字 FEC、密码上下文和管理软件是独立的大工作项。G1 冻结模块数、工具、流水与资源预算后再给可信工期，而不是承诺短期写完若干 `.v` 就代表完整协议。

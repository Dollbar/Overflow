# Native burst diagnostic into the existing Endpoint role fault owner

The native Request envelope preserves 184 bits, including Command[27:22] and NumBeats[86:85], but the production top has no confirmed decoder covering every native command. This candidate therefore adds explicit input `i_req_class_known` and `i_req_has_data`, sampled with the raw `i_rx_req_valid` event. The caller must supply a confirmed command classification from the same event. No inference from incoming Data, NumBeats, local TX candidates or speculative opcodes is permitted. Idle qualifiers are ignored; an active burst retains original VC/count across later no-data Requests. Unknown valid classification fails closed. Incorrectly asserted known/no-data cannot be recognized as a lie without the external decoder; this is an explicit boundary.

One `upli_native_rx_burst_monitor` observes raw native Request/OrigData and the pre-existing RX TDM `phase_known[0]/expected_port[1:0]`. NumBeats comes from Request[86:85]; Data Offset/Last come from Data[3:2]/[1]. The observer has no independent TDM, credit, Drop, ready or backend owner. Its current diagnostic is ORed into existing `kind_order[0]` as a local Request/OrigData burst consistency reason. Both channels belong to Completer; non-TL Drop covers all Completer ports, TL Drop covers both roles. Public `o_rx_burst_error[9:0]`, `o_rx_burst_error_sticky[9:0]`, `o_rx_burst_active[PORTS]` retain precise diagnostic provenance; the existing 32-bit reason bitmap records order/Request bit20. This is local fail-stop policy, not a claim that burst consistency errors are native parity errors.

Only common synchronous reset clears observer and existing fault controller state. Acknowledgment only clears notification. Current error must reach the existing controller before the sampling edge so native bad traffic cannot be accepted into storage. The observer freezes after first error; it is not reset by Drop. Exceptional aborted bursts after unrelated Drop may add a diagnostic until common reset; no automatic Isolation recovery is added. Credit return ownership and existing receiver bookkeeping remain unchanged. Source accepted, source captured and backend/header acceptance remain distinct; this candidate connects no backend.

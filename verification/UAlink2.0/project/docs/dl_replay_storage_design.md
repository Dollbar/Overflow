## 已核对的外部模型契约

授权依赖根通过参数传入，不写死在产品代码。文件相对根为`Library/models/kd28/fifo/rtl/kd28_fifo_sdp_storage_map.v`、`sram/rtl/kd28_sram_sdp_model.v`和固定单元模型`kd28_sram_cells.v`。读使能和地址在posedge采样，读数据在该沿后更新；无读使能时Q保持。写亦在posedge提交，模型同址同沿为读先于写。多bank映射在同一个读沿登记bank选择。

## 建议实现：完整字事务与一个输出保持槽

采用同域SDP映射，逻辑深度由控制器管理，深度1使用可用物理映射但不增加可发布容量。数据宽度为整字节可配置的不透明payload宽度，另外存储9位序号及7位对齐零；该参数不擅自声明真实线上Flit长度，完整DL字段绑定另按规范完成。

正常源事务将payload和控制器分配的序号写入真实SRAM，同时在输出槽保存正常payload/元数据。Replay事务按控制器提供地址发起已保证返回的同步读，在同一采样沿把序号、first、源类型及输出有效性登记；沿后的SRAM Q与这些元数据对齐。Q本身是Replay内容的保持寄存器，无需再复制整个缓存到寄存器。

输出槽满且下游不消费时，禁止新读请求，确保Q不被替换；正常源数据寄存器、序号/first/valid也保持。输出槽空或将被消费时，可以接受一个新事务，实现连续每周期一个已提交事务的流水能力。正常push与Replay读取由控制器互斥，不依赖未定义的同址读写旁路。复位/链路清除丢弃有效状态，但不清SRAM内容；复位之后不能发布旧Q。

重要：控制器的`i_replay_take`必须与**实际获准的存储事务及输出槽所有权转移**对应。若以读请求采样沿作为提交沿，需要在新的集成周期契约和独立参考中证明：内容在该沿被捕获到保证保持的SRAM输出Q，槽有效性与Q沿后同步出现，新写不能破坏已经转移到Q的内容。不能仅凭组合`replay_valid`宣称数据已返回，也不能直接沿用“数据先前已就绪”的调用约束而不解释这种同步提交方式。若这个契约未得到实际仿真/内容证明支持，应保留独立读取预约与最终take阶段。

## 必须先写出的独立检查

- 先建立输出槽周期参考：输入事务在采样沿提交，输出沿后出现；同拍旧输出消费和新事务替换分别记账，未消费时完整payload/元数据稳定。
- 唯一payload令牌与原TxReplay不可变内容模型对应；检查输出实际SRAM数据、保存的9位序号和控制器提供的序号一致，不从DUT输出生成期望。

- 地址/序号错接、读使能遗漏、写入错误、输出停顿期间覆盖Q、valid早/晚一拍、first与最后Replay错配等真实RTL故障必须被检查器检出。
- 控制与实际存储全部共享一个真实时钟；读返回不能抽象为任意正确值。随后开展完整内容证明及实际库/宏映射、原预算STA。

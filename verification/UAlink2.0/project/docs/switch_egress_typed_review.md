# Switch queued typed egress integration review

The candidate supplies `switch_egress_typed_pipeline` and an opt-in `ualink_switch_top` patch. The helper instantiates exactly one published pipeline and one published repack. The top retains its unique route lookup; in buffered mode its result admits explicit packet headers into that helper. Body traffic uses the previously accepted queue owner and separate `i_packet_body_token`, so subsequent route/header noise cannot rewrite ownership. No second arbiter/fabric path is active in buffered mode. Default mode preserves the original packet fabric. The fixed544 buffered profile rejects other record widths through elaboration.

The helper and buffered top each pass the full 1/2/4 ports × 1/2/4 VC matrix. Their testbench uses an admission journal, a queue-capacity journal and an independent per-egress repack register model. Expected payload words are copied from actual accepted body stimulus into a packet array and compared in order; they are not generated from DUT output or recomputed by the stimulus pattern function. A class/VC/token check precedes payload indexing. The queue-to-repack handshake is observed at named internal inter-module wires solely to distinguish the two real ownership events; those wires do not provide the expected word, fields, packet length or saved source context. All 544 output bits are compared both as a record and as header24/aux6/msg2/flit512 plus saved token/VC/class/last. Register replacement, sustained backpressure, body bubbles, packet locks and common-reset cancellation are exercised.

Queue release occurs when the packet's last word is captured into repack, possibly before typed downstream retirement. Both tests keep separate counts and check release-units against the original admission. The final canceled packet contributes a captured word but no corresponding downstream word/packet completion; this difference is intentional. Buffered-top tests additionally fill repack with a one-word packet whose queue reservation is already zero, then reject a route-table commit while only that typed word remains. All nine configurations check quiescence against the independent reservation journal and expected typed occupancy. After idle atomic route initialization, source-major headers resolve through the top's existing route lookup. The top error output distinguishes egress errors from the unused old fabric error in buffered mode.

Five actual helper wiring faults compile and fail: bypassing repack ready, corrupting payload bit0, zeroing response class, zeroing VC and zeroing Last. Three actual top wiring faults compile and fail: ignoring repack-valid in quiescence, feeding live header token to body and replacing the unique route result with all-hot destinations. These establish checker sensitivity for the listed faults, not exhaustive mutation coverage. `missing_red.log` records absent-helper elaboration failure before helper RTL was created. Early top lint failures and the ambiguous mutation-anchor runner failure are retained in their original directories; final `top_final` uses a uniquely scoped buffered-route anchor.

Validation: helper9 configurations × g2001/strict Verilator/Yosys =27 checks; buffered-top9 ×3 =27; default-top1/2/4 ×3 =9, for 63 passing static checks. Yosys runs hierarchy/proc/opt/check-assert/stat and checks zero latches and unique helper/repack/scheduler/queue ownership counts. The helper uses strict Verilator `-Wall` without waivers. Full tops retain pre-existing planned scaffold instances whose disconnected outputs and unused inputs trigger hundreds of warnings; exact-file waivers cover only `PINCONNECTEMPTY`/`UNUSEDSIGNAL` in those existing planned/scaffold sources. New top/helper and implemented datapath files receive no waivers. Full raw first-lint failures are preserved rather than called strict unwaived passes. This is structural synthesis validation, not PPA or a physical SRAM mapping signoff.

Default compatibility is checked using the published `run_switch.py` independent TB against both the frozen prior production top and candidate, at ports2/4. Both pass with identical PASS coverage lines; ports1 default is covered by static checks. This is regression evidence, not formal equivalence. New typed/header/release outputs are zero in legacy mode; new packet inputs are explicitly inactive. Existing default route/fabric behavior and data width are retained.

Install only the exact release-manifest files and review `install.patch`; the production replacement is the top, while the helper is a new source. Normal release runners use project-relative paths and create fresh results under `build/verification/ip_tops`. The separate legacy regression runner requires an explicit pre-install `--baseline` top source; it never silently compares the new top to itself. Candidate tests were executed; release path transformations are recorded but the release layout has not been separately replayed in this checkpoint.

Open standard boundary: the 544-bit local record carries existing DLheader24, aux6, msg2 and already packed TLflit512. This candidate does not reconstruct or invent `tl_tx_prepared` Control/Data/Auth groups, terminate per-port TL/DL, regenerate hop headers, classify standard traffic, generate packet metadata, prove network deadlock freedom, or connect a physical link. Buffered callers must supply trusted packet length/class/VC/token before any body beat. Fairness inherits finite-packet/eventual-ready assumptions. Reset cancels queue and repack ownership together and is not protocol LinkDown recovery. Production RTL, inventory and publication remain untouched by this isolated task.

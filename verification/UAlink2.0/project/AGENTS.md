# UALink project rules

## Scope and isolation

- 本项目以正式 UALink 规范为线协议依据；当前研究目标为 Common 2.0 与 200G DL/PL 2.0，配套规范分别锁定版本。
- 保留其他工程的工作区、分支、文件及测试结果。不得从 KDLink 自动继承报文、地址位宽、VC 数、CRC、拓扑、带宽目标或签核成绩。
- 用户已授权本地 Git 版本与分支管理；可以在完成范围审查后创建本地提交、分支和阶段标签，保留原工作区改动。提交身份使用明确配置或经确认的自动化身份。
- 推送、创建 PR、配置远端及接受外部协议仍须另行明确授权；本地管理权限不等于对外发布许可。
- 工程源文件（含 .v/.sv、pkg、VIP）、脚本、配置及普通文档名不得带版本号；版本在内容、清单和发布状态说明中记录。

## Evidence and implementation

- 公开介绍、旧版资料、规范条文、实现建议、实测结果必须明确区分。
- 缺失的格式、状态机、常量不得凭经验补齐为“UALink 标准”；应保持待确认。
- 每项协议要求记录文档修订版、章节、适用角色、mandatory/optional 条件、RTL/model/test/coverage 的映射。未拿到正文时不得伪造章节号。
- 优化可以改变内部微架构，不得擅自改变对外协议语义或编码。
- 调研阶段不生成伪实现或宣称已通过仿真。进入 RTL 工作前按适用技能执行分析、验证和审核。

## Dependencies and reproducibility

- 构建路径相对工程根目录解析；外部依赖用显式配置传入，不绑定个人主机、账号或相邻工程目录。
- 规范正文、PDK、Liberty、SerDes 模型和商业 VIP 按权限隔离，默认不入库；不能把 .gitignore 当作访问控制或许可授权。
- 未经用户明确授权，不填写身份资料、接受 EULA 或购买 IP；获授权时仅使用用户提供的信息和指定用途，提交记录留在私有目录。实施、制造和公开发布的权利仍由负责人确认。
- 接入依赖时记录来源、版本、校验值、接口、用途与可分发性。项目源代码许可证单独审批。
- 在生成 Vivado/Vitis 或目标器件脚本前，向用户确认完整器件/板卡、工具版本和设计目标，并读取相应工具参考文档。

## Verification and claims

- 协议功能、性能模型、数字 PHY 仿真、模拟 SerDes 验证、STA 和真实互操作分开报告。
- 自研 VIP 与 RTL 互测不等于独立一致性验证；至少计划规范向量或独立参考的交叉检查。
- 覆盖率列明类型、分母、排除项、工具、配置、种子和运行证据。禁止将旧工程成绩移植至本项目。
- 自测通过不等于联盟认证。所有完成声明必须限定实现 profile、适用条款和未覆盖项。

# v0.1 Scope and Acceptance

## Release Positioning

`v0.1` is the model-to-RTL architecture and repository baseline, not a runnable Kimi-K3 product. It ensures
that model, compiler, runtime, simulator, RTL, and verification work from one target and one set of
versioned interfaces.

## Required Deliverables

- OF-5P6T workload and logical-capacity baseline.
- System context, model-to-RTL boundaries, and cross-layer interface ownership.
- Monorepo structure with English README files.
- Requirement IDs mapped to owner directories, verification methods, and evidence states.
- Version, branch, dependency, release, and contribution rules.
- Placeholder areas with clear ownership for model, compiler, ISA, ABI, RTL, KDLink, and verification.

## Explicit Non-Claims

- Kimi-K3 weights have not been executed by this release.
- The 5.6T workload and 32-node fabric have not been implemented.
- The 2-PFLOPS-equivalent NPU target has not been demonstrated.
- Logical clock and bandwidth targets are analytical assumptions unless a report states stronger evidence.

## Exit Criteria

1. Root documentation and all first-level README files are English and have valid relative links.
2. `config/system_baseline.yaml` parses successfully and declares the RTL boundary.
3. Each initial requirement has an owner, verification method, evidence level, and state.
4. Architecture, specification, configuration, and traceability documents agree.
5. The Git worktree contains no model weights, credentials, private datasets, or generated build caches.
6. `make check` reports `REPOSITORY_GATE_PASS`.

Only then may the project create the `v0.1.0` tag.
